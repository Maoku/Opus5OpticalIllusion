# Room D — Opus 棟「絵にできない錯視」

> *The Opus Wing — Illusions That Cannot Be Photographed*

[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) の Room A〜C に追加する、オリジナル展示のみで構成された第4の部屋の設計書。

---

## 0. この部屋のコンセプト

Room A〜C に並ぶのは、カフェウォールもエイムズの部屋もペンローズの三角形も、すべて **「写真1枚で成立する」錯視**である。つまり本来は 3D エンジンを必要としない。3D 化はあくまで「体験としての厚み」を足しているに過ぎない。

Room D はその逆を行く。**スクリーンショットを撮った瞬間に消滅する錯視だけ**を集める。

成立条件として、次のいずれかを必ず要求する:

| 条件 | 意味 |
|---|---|
| **観測者が動くこと** | 単一の静止画では錯視が発生しない |
| **時間が流れること** | 変化・記憶・順序が知覚の材料になる |
| **音が鳴ること** | 聴覚が視覚の解釈を書き換える |
| **観測者の身体が改変されること** | 一人称視点でしか不可能な操作 |
| **観測者の視線が入力になること** | 「見ていないこと」自体が仕掛けの一部 |

各展示のキャプションプレートには共通の一文を刻む:

> **この展示はスクリーンショットでは伝わりません。**

これが Room A〜C との対比を作り、ミュージアム全体に「なぜブラウザ3Dで作ったのか」という答えを与える。

---

## 0.1 「オリジナル」の範囲について（正直な注記）

先に明確にしておく。以下の展示は **作品としてオリジナル**であり、この構成・演出・インタラクションの組み合わせは既存展示の模倣ではない。ただし **知覚現象そのものを新発見したという主張ではない**。

| 展示 | オリジナリティの所在 | 下敷きにしている既知の現象・先行例 |
|---|---|---|
| D1 二つの真実 | 1つの彫刻に**相反する2語**を同居させた構成 | 分散型アナモルフィック彫刻（Michael Murphy, James Hopkins 等） |
| D2 縮んでいく部屋 | 視点高さドリフトを**展示として自覚させる**構成 | 眼高による大きさ・距離知覚（eye-height scaling, Sedgwick） |
| D3 後ろの正面 | 視錐台外の変化を**展示のルール**にした構成 | 変化盲（change blindness, Rensink/Simons） |
| D4 聞こえる衝突 | 音のON/OFFを**来館者自身に握らせる**構成 | 跳ね返り／すれ違い錯覚（Sekuler et al. 1997） |
| D5 嘘つきの影 | 光源角度を**来館者が回せる**構成 | 影絵彫刻／Shadow Art（Mitra & Pauly 2009） |
| D6 縞の下の嘘 | 実光源のゴボ投影で**実物体に**適用した構成 | Munker–White 錯視 |

つまり「新しい錯視の発見」ではなく **「新しい錯視体験の設計」** である。ここを誇張しないほうが、展示の解説文（`reference` フィールド）も誠実に書ける。

## 1. 展示カタログ

### D1 —「二つの真実」/ *Two Truths* 🥇本命

**何が起きるか**

大広間の中空に、数百個の小さな板片が糸で吊られたように浮かんでいる。ただの塵の雲にしか見えない。

床の視点マーカー **A** に立つと、断片が一斉に整列して漢字 **「真」** を結ぶ。
反対側の視点マーカー **B** に立つと、**まったく同じ断片が** 漢字 **「偽」** を結ぶ。

**なぜ画像では成立しないか**
2枚の写真を並べれば「別の彫刻だ」と思われて終わる。同じ物体の周りを自分の足で歩いて回り、途中の無意味な状態を見て初めて「1つの物体だった」という驚きが成立する。移動が作品の一部。

**実装**

```
1. 「真」をオフスクリーン Canvas にラスタライズ → ストローク上を N 点サンプリング
2. 視点 A から各点へレイを飛ばす        → rayA[0..N]
3. 「偽」でも同様に、視点 B から       → rayB[0..N]
4. rayA[i] と rayB[j] のマッチングを解く（貪欲で十分。評価値 = 2直線の最近接距離）
5. 各ペアの最近接点の中点に断片を配置
6. 断片の法線 = 2つの視線方向の角二等分ベクトル（両視点から面が見える）
7. 断片のスケール ∝ 各視点からの距離（見かけの大きさを一定に保つ）
8. 制約チェック: 同一視点から見て角度が近すぎる断片対は除去（相互遮蔽の防止）
```

必要な新規ユーティリティ:

```ts
// src/utils/math.ts
/** 2本のレイの最近接点対と、その距離を返す */
export function closestPointsBetweenRays(
  o1: Vector3, d1: Vector3,
  o2: Vector3, d2: Vector3,
): { p1: Vector3; p2: Vector3; distance: number };
```

配置計算は**ビルド時ではなく初期化時に実行**してよい（N=300 程度なら数 ms）。文字を差し替えて遊べる利点がある。

**reveal 演出**
カメラが A から B へ**弧を描いてゆっくり移動**する。途中で文字が完全に崩壊して意味を失い、B で再結晶する。文字が崩れている時間こそが種明かし。

**多言語対応: 文字は日本語のまま固定する（確定方針）**

英語版でも **「真」「偽」の字形をそのまま使う。** TRUE / FALSE には置き換えない。断片配置は locale 非依存の単一解となり、`build()` は言語を知らなくてよい。

意図的な選択であることを、英語版の展示説明で明示的に伝える。

理由は3つあり、いずれも作品にとって前向きなものである:

1. **作品の主題は言語ではなく形である。** 読めない人にとってこの彫刻は「無意味な塵から形が立ち上がり、歩くと別の形になる」という、より純粋な体験になる。読める人が得る意味の反転は、そのボーナスにすぎない
2. **漢字のほうが点群として美しい。** 「真」10画・「偽」11画は密度がほぼ等しく、同一の断片数で両方を構成できる。TRUE(4字) / FALSE(5字) のラテン文字はストロークが疎で、断片数が減り、雲としての見応えが落ちる
3. **読めないことが再訪を生む。** 英語話者は「読めない2つの形」を見た後にキャプションで意味を知り、**もう一度両方の視点に立ちに戻る。** この往復こそが「動いたのは彫刻ではなく自分だ」という本作の主題そのもの

**⚠️ ただし新しい課題: reveal の瞬間の意味が届かない**

日本語話者は字が結ばれた瞬間に意味を理解するが、英語話者はキャプションを読むまで理解できない。**タネあかしの山場と意味の到達がズレる。**

対策 — **字が結ばれた直後に、字の脇へグロスラベルを出す**:

- ViewSpot へのスナップ完了から 0.4 秒後、字の右下に小さなラベルをフェードイン
- 表示内容は辞書の `glyphGloss` から引く。`ja` では空文字 → **描画しない**（日本語話者には冗長かつ無粋）
- `en` では `真 — “true”` / `偽 — “false”`
- **必ず字が結ばれた後に出す。** 事前に出すと reveal を台無しにする

これで英語話者も、形が立ち上がった瞬間と意味を知る瞬間が一致する。

**キャプション文（下書き）**

> **二つの真実**
> ひとつの彫刻が、立つ場所によって「真」とも「偽」とも読める。
> 断片はひとつも動いていない。動いたのは、あなただけ。

> **Two Truths**
> The characters are Japanese, and they are left that way on purpose.
> 真 means *true*. 偽 means *false*.
> Whether or not you can read them, nothing about this sculpture has changed
> between the two viewpoints. The only thing that moved was you.

`GlyphSampler` は locale 非依存になったが、**任意の文字列を受け取る汎用実装のままにしておくこと**（必須ではないが推奨）。調整段階で字を差し替えて試せる利点が残る。

**難易度**: 高（2.5日）／**インパクト**: 最大

### D2 —「縮んでいく部屋」/ *The Shrinking Room* 💰コスパ最強

**何が起きるか**

何の変哲もない廊下。入ってから約 60 秒かけて、**プレイヤーの目線の高さが 1.60m から 1.15m へ非線形に下がっていく**。気づけないほどゆっくり。

来館者は自分が縮んでいるとは思わず、**「この部屋、だんだん天井が高くなってないか？」** と感じる。廊下の出口には、入室時のあなたの目線の高さを記録した水平レーザーラインが引かれている。**それが自分の頭上を通っている。**

**なぜ画像では成立しないか**
改変されているのは展示物ではなく **観測者の身体そのもの**。一人称視点を持つ媒体でしか実行できない。

**実装**
`PlayerController.eyeHeight` を時間の関数にするだけ。実装コストは全展示中で最小、体験のインパクトは上位。

```ts
// ゾーン滞在時間 t に対して
eyeHeight = lerp(1.60, 1.15, easeInOutSine(clamp(t / 60, 0, 1)));
moveSpeed *= (eyeHeight / 1.60) ** 0.5;  // 歩幅も縮める（気づかれにくくする）
```

**reveal 演出**
目線高さの推移グラフをパネルに表示し、同時に **0.4 秒で元の 1.60m へ一気に戻す**。部屋のほうが縮んだように感じる。この「戻し」の瞬間が展示の山場。

**リスク**: 3D酔い。**必ず** `prefers-reduced-motion` で無効化し、設定にも独立トグルを置く。入口に注意書きプレートを設置。

**難易度**: 低（0.5日）／**インパクト**: 大

### D3 —「後ろの正面」/ *Behind You*

**何が起きるか**

回廊に 12 体の小さな彫像が並ぶ。ひとつずつ見ながら歩く。何も起きない。

しかし彫像は、**あなたの視界に入っていない間だけ**姿勢を変え、向きを変え、隣と入れ替わる。振り返っても、そこにあるのは「ずっとそうだった顔」をした彫像だけ。

回廊を一周し終えると、入口の扉が閉まっていて、こう書かれている。
**「12体のうち、9体が変化しました。」**

**なぜ画像では成立しないか**
仕掛けの発火条件が **観測者の視線そのもの**。見ていないことが入力になっている。

**実装**
- `Frustum.containsPoint()` + 遮蔽レイキャストで各彫像の「現在見られているか」を毎フレーム判定
- 加えて「注視されたか」（画面中央 20° 以内に 0.3 秒以上）を履歴として記録
- 非可視かつ直近 2 秒以内に注視されていない個体のみ、変化をキューから適用
- 変化は**必ず 1 フレームで完了**（補間すると視界復帰時に動きが見える）

**reveal 演出**
回廊の入口へ戻され、変化した彫像に before 状態の半透明ゴーストが重なる。「見たはずなのに見ていなかった」ことが同時に9体ぶん突きつけられる。

**難易度**: 中（1.5日）／**インパクト**: 大

### D4 —「聞こえる衝突」/ *Audible Collision* 💰コスパ良

**何が起きるか**

台の上で、2つの球が斜めの軌道で近づき、重なり、離れていく。無音で見ると、**2つの球はすれ違っている**ようにしか見えない。

台には大きな物理ボタンが1つ。押すと、球が重なる瞬間に「カツン」と短い音が鳴る。
**同じ映像のまま、球は跳ね返って衝突するようになる。**

ボタンを何度押しても、音の有無だけで解釈が反転し続ける。**自分の脳が書き換わる瞬間を自分で操作できる。**

**なぜ画像では成立しないか**
時間と音が成立条件。静止画は言うまでもなく、無音動画でも半分しか成立しない。

**実装**
- 球2つの等速直線運動。WebAudio で 20ms のクリック音（衝突時刻に同期）
- ボタンはワールド内の 3D オブジェクト（レイキャストで押下）
- Phase 7 の autoplay 解除処理が前提

**reveal 演出**
片方の球にのみ色付きの軌跡トレイルを表示 → 実際には常にすれ違っていることが一目瞭然になる。その状態で音を鳴らしても、もう跳ねて見えない。

**難易度**: 低（0.5日）／**インパクト**: 中〜大

### D5 —「嘘つきの影」/ *The Lying Shadow*

**何が起きるか**

台座の上に、意味をなさない金属の塊。左のスポットライトが落とす影は **鳥**。右のスポットライトが落とす影は **魚**。同じ塊が、同時に、2つの嘘をついている。

台座のダイヤルを回すと光源が動く。中間の角度では、影は何の意味も持たない染みに戻る。

**なぜ画像では成立しないか**
静止画にすると「2つの影絵が並んでいる」だけの絵になる。**光源を自分で回して、意味が生成され崩壊する連続を見る**ことが体験の本体。

**実装 — Visual Hull による形状生成**

```
1. 「鳥」「魚」のシルエットを 2枚の白黒 PNG として用意
2. ボクセルグリッド（例 128³）を用意し、全ボクセルを ON で初期化
3. 各ボクセルを光源 L1 からシルエット平面へ投影 → 鳥の外なら OFF
4. 同様に L2 と魚で判定 → 外なら OFF
5. 残ったボクセル集合 = 両方の影を同時に満たす立体（visual hull）
6. Marching Cubes でメッシュ化 → 簡略化 → glTF として書き出し
```

これは **ビルド時に Node スクリプトで実行**し、成果物を `public/models/` に置く。ランタイムコストはゼロ。数学は単純で、失敗しない。

> 注意: 2つのシルエットは「互いに矛盾しすぎない」必要がある。visual hull が痩せすぎると影が欠ける。シルエットの選定は試行錯誤が要るので、**スクリプトを先に作って複数の組み合わせを試せるようにする**。

**reveal 演出**
ダイヤルが自動で 180° 回り、影が鳥 → 無意味 → 魚 と変化する。同時に塊がワイヤーフレーム化して voxel hull の実体を見せる。

**難易度**: 中〜高（2日、うちシルエット調整に時間）／**インパクト**: 大

### D6 —「縞の下の嘘」/ *Under the Stripes* 💰コスパ良

**何が起きるか**

**まったく同一のマテリアル**で作られた球が6つ、台の上に並ぶ。天井から縞模様の光が降っている。球は明らかに違う色に見える。オレンジ、ピンク、緑、水色。

球の周りを歩いても、しゃがんでも、近づいても、色の違いは消えない。**実光源による投影**なので、視点をどう変えても効果が持続する。

**なぜ画像では成立しないか**
2D の Munker 錯視は「そういう画像だから」で片付けられる。実物体・実光源・自由な視点移動が揃うと、逃げ場がなくなり **「絶対に色が違う」という確信**が生まれる。その確信を裏切ることが展示の目的。

**実装**
- Three.js の `SpotLight.map` に縞模様テクスチャ（ゴボ）を設定するだけ
- 球は完全に同一の `MeshStandardMaterial` インスタンスを共有（これがミソ。デバッグ時も同一性が保証される）

**reveal 演出**
1. 縞の光がフェードアウト → 6球が同色になる
2. さらに6球が中央に集まって重なり、完全に一致することを示す

**難易度**: 低（0.5日）／**インパクト**: 大（体感の裏切り幅が最大級）

### D7 —「果てのない回廊」/ *The Endless Cloister*（ストレッチ目標）

4回右に曲がると元の場所に戻らず、部屋の外周より内側のほうが広い非ユークリッド空間。ポータルレンダリング（RTT + ステンシル）で実装。

**難易度**: 高（3日以上）／単独のマイルストーンとして分離し、他が全部終わってから着手する。**やらなくても Room D は成立する。**

## 2. 実装への影響（既存設計の変更点）

Room D は既存の型・システムに **3つの拡張**を要求する。Phase 4 の設計時点でこれを織り込んでおくこと。後付けは高くつく。

### 2.1 複数 ViewSpot の許容（D1 が要求）

```diff
- viewSpot?: ViewSpotDefinition;
+ /** 単一視点でのみ成立する展示。D1 のように複数の正解視点を持つ場合は複数要素 */
+ viewSpots?: ViewSpotDefinition[];
```

`ViewpointController` は「今どの ViewSpot にロックしているか」を index で保持する。`reveal` 演出が ViewSpot 間の移動を伴うケース（D1）にも対応が必要。

### 2.2 ゾーン型展示の導入（D2・D3 が要求）

D2「縮んでいく部屋」と D3「後ろの正面」は、**台の上に置かれた物体ではなく、部屋そのものが展示**である。

```diff
+ export type ExhibitKind = 'object' | 'zone';

  export interface ExhibitDefinition {
+   kind: ExhibitKind;
+   /** kind === 'zone' のとき、進入判定に使う AABB */
+   zone?: { min: Vector3Like; max: Vector3Like };
```

`ExhibitManager` にゾーン進入・退出イベントを追加し、ゾーン型展示は `onEnter` / `onExit` / 滞在時間 `t` を受け取れるようにする。

### 2.3 プレイヤー状態への書き込み権限（D2 が要求）

D2 は `PlayerController` の `eyeHeight` と `moveSpeed` を書き換える。展示がプレイヤーを改変できる経路が必要。

```ts
export interface BuildContext {
  // ...既存
  /** 展示がプレイヤー状態を一時的に上書きするためのハンドル。
   *  ExhibitManager が退出時に必ず巻き戻す責任を持つ */
  playerOverride: PlayerOverrideHandle;
}
```

**巻き戻しの保証が最重要。** ゾーンを出たら必ず元に戻ること、`dispose()` でも必ず戻ることをテストで担保する（縮んだまま他の部屋に行けてしまうと、他展示の錯視が全部壊れる）。

### 2.4 新規ユーティリティ

| 追加物 | 用途 | 使う展示 |
|---|---|---|
| `closestPointsBetweenRays()` | 2視線の交点解決 | D1 |
| `GlyphSampler`（Canvas → ストローク点群） | 文字の点群化 | D1 |
| `VisibilityTracker`（視錐台+遮蔽+注視履歴） | 「見られているか」判定 | D3 |
| `tools/buildShadowHull.ts`（Node スクリプト） | Visual Hull 生成 | D5 |
| `AudioBus`（WebAudio ラッパ） | 同期クリック音 | D4 |

`VisibilityTracker` は D3 専用に見えるが、**Phase 4 の展示カリング（20m 超は update 停止）とロジックを共有できる**。先に汎用として作る。

## 3. 段階導入と工数

Room D は全部作らなくても成立する。**コストと効果が釣り合う順**に3段階へ分ける。

### Tier 1 — 「安くて強い」3点 〔合計 1.5日 + 部屋 0.5日〕

| 展示 | 工数 | 依存 |
|---|---|---|
| D2 縮んでいく部屋 | 0.5日 | 2.2 ゾーン型 + 2.3 プレイヤー改変 |
| D4 聞こえる衝突 | 0.5日 | Phase 7 の音声解禁 |
| D6 縞の下の嘘 | 0.5日 | なし（`SpotLight.map` のみ） |

**この3点だけで Room D は展示室として成立する。** コンセプト（絵にできない錯視）も、身体・時間・音・色という4つの切り口も揃う。**まずここまでを確定スコープにすることを推奨。**

### Tier 2 — 「本命」3点 〔合計 6日〕

| 展示 | 工数 | 依存 |
|---|---|---|

## 4. 順路と部屋の設計

```
      [エントランス]
            │
   ┌────────┼────────┐
   │        │        │
[Room A]  [Room B]  [Room C]
 平面の    あり得    空間と
 だまし絵  ない立体   身体
   └────────┼────────┘
            │
      ┌─────┴─────┐
      │  Room D   │   ← 他3室をすべて訪問すると開錠
      │ Opus 棟   │
      └───────────┘
```

**Room D は最初は施錠しておき、Room A〜C の展示を一定数見ると開く。**

理由は演出上のもので、Room D の価値は「既存の名作錯視を一通り見た後」に最大化されるため。「錯視とは絵の中にあるもの」という前提を Room A〜C で十分に固めてから、それが崩される部屋に入る、という順序が効く。

**内部の順路**: D6（色）→ D4（音）→ D3（記憶）→ D2（身体）→ D1（大広間・看板作品）
段階的に「疑われる対象」が **展示物 → 自分の知覚 → 自分の身体** へ移っていく構成。

## 5. リスク

| リスク | 対策 |
|---|---|
| **D2 で 3D 酔い** | `prefers-reduced-motion` 対応必須、独立トグル、入口に注意書き。ドリフト時間を60秒→90秒に延ばす選択肢も用意 |
| **D2 の状態が巻き戻らず他室の錯視を破壊** | `playerOverride` の巻き戻しを Vitest で担保。退出時・dispose時・ワープ時の3経路すべてをテスト |
| **D1 の断片配置が汚くなる**（相互遮蔽・可読性不足） | マッチングを貪欲法で実装後、角度分離の閾値をパラメータ化して調整可能に。文字を画数の少ないものに変更できる余地を残す |
| **D5 の visual hull が痩せて影が読めない** | ビルドスクリプトを先に作り、シルエットの組み合わせを複数試す。最悪、2つのシルエットの角度差を 90° から狭める |
| **D3 が「バグに見える」** | 変化は必ず 1 フレームで完了させる。reveal で必ず「これは意図的である」ことを明示する。キャプションで先に予告しない（予告すると成立しない）ため、reveal 側の説明責任が重い |
| **D4 が autoplay ポリシーで無音のまま** | Phase 7 の「クリックして入場」で AudioContext を確実に解禁。未解禁時はボタンに「音を有効にする」表示を出す |
| **D6 が color management 設定に敏感** | Phase 7 の後処理追加後に必ず再検証（Room A のチェッカーシャドウと同じ扱い） |
